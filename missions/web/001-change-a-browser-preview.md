# 🌐 Mission WEB-01 — Change a Browser Preview

**Track:** Web development

## Where am I?

One existing browser showcase used as reference/practice, not as proof Connor built it.

## What am I learning?

The roles of HTML, CSS and JavaScript in a visible browser experience.

## What do I do next?

1. Open one existing browser preview.
2. Connor identifies one visible element and guesses whether structure, style or behaviour controls it.
3. Antigravity verifies the relevant file.
4. Connor chooses one small visual or behavioural change.
5. Make the bounded change.
6. Reload the browser.
7. Check the requested change and one nearby behaviour for regression.
8. Inspect the diff.

## How do I run it?

Use the existing local browser files; do not introduce a framework or server unless the current project actually requires one.

## How do I know it worked?

Connor can identify whether the change was mainly HTML, CSS or JavaScript and verify the browser result.

## Connor decides

Connor chooses the visual/behavioural change.

## Tracker evidence

Do **not** promote capability merely because Antigravity completed the work.

Potential evidence from this mission:

- EXPLANATION: HTML/CSS/JavaScript responsibility.
- DECISION: requested browser change.
- VERIFICATION: browser observation plus diff inspection.

## Harder challenge

Use browser developer tools to inspect the changed element or console state and explain one thing the tool reveals.
