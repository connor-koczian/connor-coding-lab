# 🧪 Mission TEST-01 — Read the Evidence

**Track:** Testing & verification

## Where am I?

A current project with an existing automated test, initially Python Basics.

## What am I learning?

What a passing test proves, and what it does not prove.

## What do I do next?

1. Inspect one test file.
2. Connor explains the input/action/expected result in plain English.
3. Run the declared test command.
4. Read the number of tests collected and the pass/fail result.
5. Identify one behaviour the test does not cover.
6. If useful, ask Antigravity how a new test could cover that gap without implementing it yet.

## How do I run it?

Use the project's declared test workflow, currently expected to be `uv run pytest` for Python Basics only after verifying the project configuration.

## How do I know it worked?

Connor can state what the observed test checks and name at least one limitation of the evidence.

## Connor decides

Connor chooses the uncovered behaviour he thinks is most worth testing.

## Tracker evidence

Do **not** promote capability merely because Antigravity completed the work.

Potential evidence from this mission:

- EXPLANATION: what the assertion/test means.
- VERIFICATION: interprets actual test output.
- DECISION: identifies a useful missing case.

## Harder challenge

Design a failing test for the missing case, predict why it should fail, then let Antigravity implement it if the plan is sound.
