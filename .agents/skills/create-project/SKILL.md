# Create Project

1. Decide whether the idea is practice or a continuing project.
2. If practice, prefer the appropriate `practice/` area.
3. If continuing, use the approved sibling-project model rather than adding a permanent monorepo subproject.
4. Let Connor choose the meaningful theme, mechanics, purpose and name.
5. Define a tiny first playable or useful milestone.
6. Choose the simplest suitable stack.
7. Use the verified repository toolchain.
8. Do not introduce Git submodules.
9. During preparation, do not assume repository ownership has transferred to `connor-koczian`.
10. Validate creation and record how to run the first milestone.
