# Start Session

1. Read root `GEMINI.md` and the current V2 master implementation plan if repository governance matters.
2. Inspect current Git branch/status before proposing changes.
3. If `progress/CONNOR-MASTER-TRACKER.md` exists, read it. If it does not exist, state that Phase 3 has not established canonical learner state and do not invent it.
4. Identify active/unfinished work from source-supported repository evidence.
5. Before naming any file, directory, command, executable or entry point in the briefing, verify that it exists in the current repository or environment.
6. Distinguish presence/configuration from validation. Do not call software or behaviour working, passing or healthy unless it was actually validated in the relevant current environment; otherwise say it exists, is configured, or is documented.
7. Summarise where Connor is, what he is learning, the next bounded action, how to run it and how success will be checked.
8. Prefer one useful next mission, with one optional harder stretch.
9. Do not modify files merely to start a session.
