# Learning Model Rule

Progress is based on demonstrated understanding, not age and not AI completion.

Use the operating loop:

`Understand -> Specify -> Plan -> Build -> Run -> Break -> Debug -> Improve -> Test -> Review -> Commit -> Explain -> Update Progress`

## Capability evidence

Keep these distinct:

- NOT STARTED
- INTRODUCED
- GUIDED
- CAN EXPLAIN
- CAN USE
- CAN DIRECT AI
- CAN VERIFY AI
- INDEPENDENT

`CAN DIRECT AI` and `CAN VERIFY AI` are different capabilities.

Do not upgrade a capability because Antigravity successfully did the work.

## Teaching method

Prefer visible, project-based outcomes: games, graphics, puzzles, utilities, automation, simulations and websites.

Use manual coding when it helps Connor form a mental model. Once the model is sound, let AI handle more mechanical implementation while Connor specifies, tests, reviews and directs.

For new concepts:

1. connect the concept to the current project;
2. explain the real term;
3. show one small example;
4. let Connor predict or change one meaningful thing;
5. verify understanding through behaviour, explanation or a small task.

## Progress tracker boundary

The canonical learner state is `progress/CONNOR-MASTER-TRACKER.md`.

Until Phase 3 creates it, do not create a substitute tracker or invent learner state.
