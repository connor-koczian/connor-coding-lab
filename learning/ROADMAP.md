# 🧭 Connor Coding Lab — Learning Roadmap

This roadmap is a **multi-track progression**, not a school-style linear textbook.

Connor can progress faster in one area than another. Advancement should follow demonstrated understanding and useful project needs rather than age or lesson count.

## The tracks

| Track | What it develops |
| --- | --- |
| 🖥️ Computer & Linux | Files, terminal, processes, permissions, software and maintenance |
| 🤖 AI-native development | Prompting, specification, context, planning, agents and verification |
| 🐍 Programming | Variables, decisions, loops, functions, data and program structure |
| 🐛 Debugging | Reproduce, observe, hypothesise, isolate, fix and verify |
| 🌿 Git & GitHub | History, diffs, commits, branches, remotes, PRs and review |
| 🧪 Testing | Evidence that software behaves as intended |
| 🎮 Game development | Input, movement, state, collision, UI, levels and architecture |
| 🌐 Web development | HTML, CSS, JavaScript and browser development |
| 🏗️ Software engineering | Requirements, architecture, dependencies, APIs, CI and review |
| 🛡️ Safety & maintenance | Credentials, permissions, dependencies, updates and safe AI use |

## AI-native progression

Connor should move roughly through these capabilities:

```text
ASK
  -> SPECIFY
  -> PLAN
  -> DIRECT AI
  -> RUN
  -> VERIFY
  -> DEBUG
  -> REVIEW
  -> SHIP A SAVE POINT
  -> IMPROVE
```

Prompt engineering is part of this, but the wider skill is **AI collaboration engineering**.

## Programming progression

Programming concepts still matter because Connor needs a mental model of what the agent is building.

Likely progression:

```text
input/output
-> variables and values
-> decisions
-> repetition
-> functions
-> lists/dictionaries/data
-> modules/files
-> simple tests
-> larger program structure
```

Manual coding is useful when it develops understanding. It should not become repetitive typing once Connor can explain and direct the concept competently.

## Git progression

```text
status
-> diff
-> specific-file stage
-> commit
-> log
-> branches
-> merge
-> pull/push
-> pull requests
-> review
```

Connor should initially perform enough operations himself to understand the model. Antigravity may then increasingly handle the mechanics while Connor reviews the intent and result.

## Debugging progression

```text
REPRODUCE
-> OBSERVE
-> HYPOTHESISE
-> ISOLATE
-> SMALLEST RELIABLE FIX
-> RERUN
-> VERIFY
```

"Ask AI to rewrite it" is not the default debugging method.

## Projects drive the roadmap

The roadmap should feed visible projects and challenges rather than becoming a checklist detached from building things.

The detailed curriculum and mission sequence will be implemented in the dedicated curriculum phase.
