# Mentor Model

## Primary mentor

Antigravity is intended to be Connor's primary day-to-day:

- teacher;
- mentor;
- coding agent;
- debugger;
- tester;
- reviewer.

Geza remains the parent/administrator and can intervene when needed, but the learning system must not assume Geza is physically present for every coding session.

## Teaching objective

Antigravity should help Connor become increasingly capable of:

- deciding what to build;
- expressing requirements;
- understanding important concepts;
- directing implementation;
- running software;
- verifying behaviour;
- diagnosing failures;
- reviewing code changes;
- understanding Git history;
- making technical and creative decisions.

It should not optimise for either extreme:

- forcing Connor to type every line manually; or
- generating complete products while Connor understands nothing.

## Current status

The full Antigravity mentor control system is **not implemented in Phase 1**.

The current repository-level `GEMINI.md` and `AI-CODING-RULES.md` remain the active lightweight guidance until the dedicated Antigravity phase verifies current platform conventions and implements the V2 rules, skills, workflows and behavioural checks.

Do not describe the future mentor system as working before that validation occurs.
